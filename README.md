# 古法编程Tello Edu无人机的智能体控制程序
注：该项目是我个人新手作品，代码纯手敲，无ai生成。代码可能不规范，作为个人项目记录，可供参考。
警告⚠：代码中包含eval()，如需ctrl+V，请谨慎使用。
本项目使用langgraph图智能体框架，实现了用户使用QQ与QQrobot对话的方式（包含文字和语音），操控Tello无人机飞行。

# 项目设计思路：
备注：大疆Tello Edu版无人机在编程环境下拥有两种控制模态：一次性命令和RC连续控制流。设计思路围绕这两种控制模态展开：

1.QQ消息处理：
  因QQrobot的消息处理是基于异步IO并发处理的，因此整个langgraph需要设置为异步图。

2.提取用户输入内容：
  用户输入内容可能包含多条指令：如"起飞，以50cm/s的速度向前飞行1m"。
  因此需要使用大模型将用户的输入内容拆分为多条单独的指令，然后存入指令队列中。
  
  注意⚠：因为无人机控制模态分为连续控制流与一次性命令，大模型需要格外区分下面两种输入：
    ①："起飞，以50cm/s的速度向前飞行1m" → 需要拆分为【起飞，设置50cm/s的速度，向前飞行1m】
    ②："起飞，以50cm/s的速度向前飞行" → 需要拆分为【起飞，以50cm/s的速度向前飞行】
    
  尤其是当用户输入内容过长、断句不明显时，容易导致连续控制流和一次性命令指令混合在一起，让大模型不容易精准提取。
  
3.处理历史信息：
  用户的输入可能携带着历史信息：如"继续刚才的指令"。
  因此设计的graph图需要配置记忆系统。可设计一个分支节点用于处理历史信息。
  当用户输入的内容包含历史信息时，交于该节点处理，处理完成后，再交由提取用户输入的节点。

4.RAG文档检索：
  有了指令队列，需要将具体的指令（可能包含人的语言修饰）精准匹配到无人机操作代码上，这样程序才能执行。
  本地存有无人机的操作手册txt文档，采用RAG技术，方便从本地文档中检索内容。
  
  注意⚠：如果只使用按字符分割的Retriever进行检索，可能会导致下面两种情况的误判：
    ①："以50cm/s的速度" → 这是属于操作手册里面的设置速度指令。
    ②："以50cm/s的速度向前飞行" → 这是属于操作手册里面的RC连续控制指令。
    
  能够提升检索质量的有很多方法，本项目采用父子文档检索技术ParentDocumentRetriever，按控制类型拆分父文档。
  将当前指令的控制模态类型用于检索，找到对应的父文档后，将父文档接入用户的输入（具体的操作）后交于大模型进行生成。

5.一次性命令执行：
  当通过RAG检索到了具体命令代码时，如果是一次性命令，便可直接执行当前命令。
  由于无人机的飞行完成需要操作时间，因此需要asyncio.sleep等待当前命令执行完毕，具体时间根据实际飞行计算。
  执行完毕后，从指令队列中删除当前指令，如果剩余指令为空，则转为END；否则，转向检索节点继续检索。

6.RC连续控制流命令的处理：
  Tello无人机的RC连续控制流指令是需要循环发送的，可以随时改变无人机的运动状态。
  因此，当前指令集执行到RC连续控制流指令时，便无法执行当前指令队列的余下指令。（个人认为符合现实情况）
  只有当用户的下一次输入到达时，中断当前RC连续控制指令，然后返回空的指令队列，结束之前用户的输入执行（此时新的用户输入已经执行）。
  因此，设置了全局变量CONCURRENCY_NUMBER，初始为0。每当进入图执行时+1，退出图执行时-1。
  RC连续控制流命令的循环执行条件是CONCURRENCY_NUMBER == 1，确保循环执行的RC命令只有一个。
  注意⚠：在并发的设计下，为了避免循环阻塞，使用await asyncio.sleep(0.05)让出执行权，0.05为连续控制流命令的发送频率。

# V1.0的问题：
1：
  将判断是否为历史信息的功能设计到了graph图里的节点，这会导致并发且带记忆系统的图在异步执行时会扰乱state状态值。
  可在图外额外添加一个智能体，将判断是否为历史信息的功能设计成为tool，随后该智能体根据该tool调用结果分配不同的thread_id。
  但是这样也只能解决用户的非历史信息输入，在面对用户快速的历史信息输入时，依旧会扰乱state值。

2：
  在RAG技术中，因为ParentDocumentRetriever不支持MarkdownHeaderTextSplitter，所以本人使用retriever.add_documents(parent_docs)
  手动添加父文档到本地向量库中。由于ParentDocumentRetriever检索器的特性，每次执行都会将父文档同时添加到本地和内存中。
  这样本地向量库会一直增长且冗余，所以我设置了if vectorstore._collection.count() == 0的时候才添加。
  可是这样在第二次执行时就无法从内存中获得父文档了，⚠⚠⚠所以除了第一次执行程序，多次执行程序无法获得父文档。
  ⚠⚠⚠推荐解决方法：除了第一次执行程序，每次执行都在当前目录下删除本地向量库文件。
